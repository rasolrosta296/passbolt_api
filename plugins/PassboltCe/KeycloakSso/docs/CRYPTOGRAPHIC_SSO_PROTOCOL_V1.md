# Keycloak cryptographic SSO protocol v1

Status: frozen for Milestone 4 implementation. This document does not change Passbolt's authentication authority.

## Security boundary

OIDC proves control of a linked Keycloak identity. It never creates a Passbolt identity, session, JWT, or refresh token. Releasing the server share also never authenticates Passbolt. Only the existing, unchanged GPGAuth/GPG-JWT challenge proof establishes Passbolt authentication.

Keycloak never receives Passbolt private keys, passphrases, client or server envelope keys, or vault plaintext. The API never receives the client key, plaintext passphrase, decrypted private key, or vault plaintext. The browser extension is the only context in which the passphrase and decrypted OpenPGP private key may briefly exist.

## Versioned context

`ContextV1` is deterministic RFC 8949 CBOR containing exactly one fixed positional array of nine text strings:

1. `protocol_version`
2. `crypto_suite`
3. `passbolt_origin`
4. `user_uuid`
5. `identity_uuid`
6. `enrollment_uuid`
7. `client_enrollment_uuid`
8. `openpgp_fingerprint`
9. `enrollment_public_key_thumbprint`

The version is `passbolt-keycloak-sso-v1`. The suite is `AES-256-GCM+HPKE-P256-HKDF-SHA256-AES128GCM`. Decoders reject non-text values, maps, tags, indefinite lengths, optional or unknown fields, non-canonical encodings, and trailing data. Accepted bytes must equal a deterministic re-encoding using a constant-time comparison.

Domain-bound messages are deterministic CBOR arrays `[domain, ContextV1]`, using these exact domains:

- `passbolt-keycloak-sso-v1/inner-aead`
- `passbolt-keycloak-sso-v1/outer-aead`
- `passbolt-keycloak-sso-v1/enrollment-transcript`
- `passbolt-keycloak-sso-v1/device-login`
- `passbolt-keycloak-sso-v1/release-package`
- `passbolt-keycloak-sso-v1/context-hash`

## Keys and persisted artifacts

- `KD`: 256-bit AES-GCM key generated by WebCrypto with `extractable=false`. It is a profile-resident non-extractable key persisted by IndexedDB structured clone.
- Enrollment signing key: ECDSA P-256 key generated by WebCrypto with `extractable=false` for the private key. It is a profile-resident non-extractable key persisted by IndexedDB; only its public JWK is sent to the API.
- `KS`: independent 256-bit AES-GCM key generated in the extension. It is extractable only during enrollment upload and is never persisted in plaintext by the browser.
- Server share protection: XChaCha20-Poly1305-IETF under a deployment KEK selected by explicit key ID. The active KEK encrypts; old keys are decrypt-only.
- Release transport: RFC 9180 base mode with DHKEM(P-256, HKDF-SHA-256), HKDF-SHA-256, and AES-128-GCM, as frozen by the compatibility prototype.

The extension persists `KD`, the signing private key, `C2`, independent 96-bit inner and outer IVs, canonical context, and public enrollment metadata. The API persists only encrypted `KS`, its KEK key ID and nonce, the signing public key and thumbprint, the SHA-256 digest of `C2`, context metadata, and ownership/status fields.

## Enrollment

Enrollment requires both an active normal GPGAuth-created Passbolt session and a fresh, one-time, purpose-bound OIDC proof for the already linked issuer and subject. The extension verifies the user's existing passphrase locally, generates fresh keys and identifiers, computes `C1 = AES-256-GCM(KD, P, innerAAD)` and `C2 = AES-256-GCM(KS, C1, outerAAD)`, and signs the enrollment transcript with the existing OpenPGP key. The API verifies session, CSRF, identity ownership, freshness, context, transcript signature, fingerprint, suite, and uniqueness before encrypting `KS` and atomically committing the enrollment. Local persistence happens only after that commit.

## Login and release

Login starts in the extension with a fresh client nonce and ephemeral HPKE recipient key. A request-bound device-login transcript is signed with the profile-resident enrollment signing key. After server verification, every unlock creates a five-minute OIDC transaction with `prompt=login`, `max_age=0`, an essential configured ACR, fresh state/nonce/PKCE, and no refresh token or silent flow. `auth_time` must fall within the server transaction window with at most 60 seconds skew; returned ACR must match exactly.

The callback creates only a one-time release capability. A second signed request atomically consumes it. The API decrypts `KS`, HPKE-seals it to the request-bound ephemeral recipient using the release-package binding, then discards plaintext `KS`. The extension opens the package, decrypts `C2` with `KS`, decrypts `C1` with `KD`, checks context and fingerprint, decrypts the existing OpenPGP private key locally, and invokes unchanged GPGAuth. All passphrase, share, decrypted-key, HPKE-private-key, and release-capability material is cleared best-effort after use.

## Revocation, logout, and rotation

Identity unlink is a normal authenticated, CSRF-protected, explicitly confirmed transaction. It locks the identity and enrollment rows, revokes and deletes enrollments and encrypted shares, then deletes the identity and returns enrollment identifiers for local cleanup. The normal encrypted OpenPGP key is untouched. Offline profile clones retain local artifacts but cannot obtain revoked `KS`.

Logout removes transient passphrase, server share, decrypted OpenPGP objects, ephemeral HPKE keys, and release capabilities. It retains the profile-resident enrollment keys and encrypted client envelope. No SSO-derived plaintext passphrase is persisted.

Passphrase or OpenPGP-key rotation revokes affected enrollments and requires re-enrollment. Issuer or subject changes require explicit identity re-linking and a new enrollment. KEK rotation rewraps `KS` under the new active key ID. Protocol upgrades create versioned new enrollments and never downgrade silently.

## Accepted first-release trust model

Desktop Chrome/Chromium is the only supported browser. A copied enrolled browser profile, qualifying fresh Keycloak authentication, and an honest available Passbolt API are sufficient for SSO unlock. The profile keys are not described as device-bound, hardware-backed, uncloneable, or proof of a physical device.
